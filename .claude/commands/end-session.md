---
description: End work safely — nothing lost, no noise committed, no history rewritten
---

You are my "end session" assistant. Help me stop work with ZERO surprises:
- Do not lose work.
- Do not commit/push noise files.
- Do not force push.
- Do not rebase.
- Ask before any action that modifies history or changes files.

**Context: two people, one shared branch, never at the same time.**
My co-founder picks up from wherever I stop. That changes what "done" means:

1. **Pushing is the default, not a question.** Work that is committed but not
   pushed does not exist as far as they are concerned. Confirm before pushing,
   but treat pushing as the expected end of every session — if I decline, say
   plainly that they will be working from stale code.
2. **Never end a session on a stash.** `git stash` is local to this machine.
   They cannot see it, pull it, or recover it. Unfinished work becomes a WIP
   commit that gets pushed, not a stash.
3. **Never end a session dirty.** Uncommitted changes are invisible to them for
   the same reason. Commit (even as WIP) or discard.
4. **`HANDOFF.md` is part of finishing.** Half-done work is only resumable if the
   next person knows what I was in the middle of.

Broken or half-finished code on the branch is fine — that is what WIP commits are
for. Invisible code is not.

**Target branch:** `$1` — if I gave no argument, use `RESURRECTION`.
**Remote:** `origin`

**Known-noise files:**
- `.DS_Store`
- any path ending in `.xcuserstate`

**Flutter build churn** (generated by `flutter pub get` / `flutter build` —
almost never worth committing, but `pubspec.lock` and `ios/Podfile.lock` CAN
carry real dependency changes, so show me the diff before discarding):
- `analysis_options.yaml`, `pubspec.lock`, `ios/Podfile.lock`
- `linux/flutter/generated_plugins.cmake`, `windows/flutter/generated_plugins.cmake`
- `macos/Flutter/Flutter-Debug.xcconfig`, `macos/Flutter/Flutter-Release.xcconfig`
- `macos/Flutter/GeneratedPluginRegistrant.swift`

Goal: leave the branch pushed, with a current `HANDOFF.md`, and nothing of mine
left only on this machine.

## Step 0 — Confirm we are in the repo
Run `git rev-parse --show-toplevel`. If it fails, STOP and tell me I opened the
wrong folder.

## Step 1 — Check working tree
Run `git status --porcelain`.

- Empty → skip to Step 2 (I may still owe a handoff update for commits I made
  earlier this session — check `git log origin/<target>..HEAD --oneline`).
- Not empty → show me the full list, then separate it into three buckets:
  1. known noise
  2. Flutter build churn
  3. real changes

If only buckets 1 and 2 remain, tell me and offer `git restore .`.

## Step 2 — Write the handoff
Do this BEFORE committing, so `HANDOFF.md` goes in with the same commit.

Read the current `HANDOFF.md` (create it from the template if missing), then
draft a replacement for me. **Overwrite it — do not append.** It is a baton, not
a diary; only the current state matters, and a fully-rewritten file cannot
conflict meaningfully.

Draft it from real evidence, not guesswork:
- `git log origin/<target>..HEAD --oneline` — what I committed this session
- `git diff --stat` — what is still uncommitted
- what I actually told you during this session

Fill in:
- **Last session** — my git `user.name` and today's date.
- **Done** — what is finished and works.
- **In progress (STOP HERE)** — the important part. Name the exact files and
  line numbers, what I was attempting, and what I already tried that did NOT
  work. Empty this section out if I finished cleanly; do not leave last
  session's entries sitting there.
- **Don't touch** — anything mid-refactor that would conflict.
- **Next** — the obvious next move.

Show me the draft and let me correct it before writing. Keep it short — bullets,
no prose. If I say there is nothing to hand off, still update **Last session** and
clear the stale sections.

## Step 3 — Finish the working tree
STOP and ask me to choose ONE:

### A) Commit (work is in a good state)
1. Show `git diff --stat`, and offer the full `git diff`.
2. Stage **by name** — `git add <path> ... HANDOFF.md`. Do NOT use `git add -A`
   in this repo; it sweeps in build churn. Offer `git add -p` to be selective.
3. Confirm with `git status`.
4. Ask me for the commit message, then commit.

### B) WIP commit (work is unfinished — this replaces stashing)
1. Stage by name, including `HANDOFF.md`.
2. Commit with a `wip:` prefix, e.g. `wip: collage grid overflow on small screens`.
3. Remind me this is deliberate: the branch will hold half-done code, and
   `HANDOFF.md` explains why. That is correct — it is how the work stays visible.

### C) Discard
Show me exactly what will be lost first, then `git restore` the paths I name.
Never discard without showing the diff.

If I ask to stash instead, tell me why that breaks this workflow (it is local to
this machine and my co-founder cannot see it) and offer B. Only stash if I insist.

## Step 4 — Health check
Run `flutter analyze` and `flutter test`, and report the result before I walk away.
Do not fix failures silently.

- Green after a normal commit → good, continue.
- Failing after a **WIP** commit → expected, note it in `HANDOFF.md` under
  "In progress" so it is not mistaken for a surprise breakage. Continue.
- Failing after a **normal** commit → tell me, and ask whether to keep it as-is,
  fix it now, or relabel the commit as `wip:`.

## Step 5 — Push
Run `git status -sb`.

- ahead → show me the commits and ask to confirm, then `git push origin <target>`.
  This is the expected end of a session. If I decline, say clearly that my
  co-founder will pull stale code and we risk diverging.
- diverged → STOP. Do not push, do not force. Explain that someone worked without
  syncing, and ask how to resolve.
- up to date → nothing to push, say so.

Never force push. Never rebase to make a push succeed.

## Step 6 — Final summary
Run `git status -sb` and `git status --porcelain`, then summarise:
- current branch
- clean / dirty after filtering
- ahead / behind / diverged (after the push, this should be up to date)
- what was done (commit / WIP commit / discarded)
- whether `HANDOFF.md` was updated and pushed
- anything my co-founder needs to know before they start
